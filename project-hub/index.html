Project Hub Guide

Project Hub, made simple

Project Hub is ERC's project management reporting tool. It replaced Project Web App (PWA), which was retired on 30 September. This guide takes the 143-slide training deck and reorganises it around the job you're actually trying to do — so you can look something up in seconds instead of scrolling for it.

Replaces PWA Schedules run in Microsoft Planner Feeds the Power BI board reports Still evolving — improvements on a backlog

How Project Hub fits together

Everything lives in one plan per project. You fill it in through tabs, and what you enter flows out to the dashboards your boards look at. Your documents live alongside it in the project's Teams site.

One thing to know before you startWhen you first create a plan, only the Summary, Business Case and Financials tabs can be completed. Tasks, Risks and Issues unlock once you've pressed Save & Close for the first time.

What's different from PWA

The headline changes the PMO highlighted. If you knew PWA, these are the things that will feel different.

No more time-outs

There's no time limit when creating a project, and the app autosaves every time you make a change.

Escalate a risk to an issue

One flow turns a risk into an issue and carries its details across — no retyping.

How →

Financials (optional)

Budget and spend can now be recorded and reported in the dashboards. Not mandatory.

How →

Schedules in Planner

Tasks are managed in Microsoft Planner — easier to add, edit and assign, with board, timeline and chart views.

How →

History is kept

Every status update is saved, not overwritten — you can look back at previous reports.

How →

Flash Report is gone

It's replaced by a 3-month look-ahead in the Status tab, plus a one-page Highlight Report.

Your first time through, in order

Setting up a new project? This is the sensible order to do things in — each step links to the detail.

  1. Bookmark Project Hub so it's always one click away. How
  2. Create the plan — complete Summary, Business Case and (optionally) Financials, then Save & Close. How
  3. Share permissions — including anyone you'll make a risk or issue owner. How
  4. Link the Teams site and paste the documents link into Project Documentation. How
  5. Build the schedule in Tasks, with your critical milestones. How
  6. Record risks and issues using the naming convention. How
  7. Submit a Status update before each board. How
  8. Move the lifecycle stage on as the project progresses. How
