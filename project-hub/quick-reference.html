Rules & common mistakes

The things the training flagged as easy to get wrong.

Always

✓
Start risk and issue names with your Project IDe.g. PRJ-1004 – Staff Resource Availability. Duplicate names are blocked.Naming →
✓
Tick Append and Append to when sharingEvery time you give someone permissions.Permissions →
✓
Give owners Read access firstSomeone can only own a risk or issue if they can read your project.Permissions →
✓
Set critical milestones to 0 daysSame start and finish date, duration set manually to 0.Milestones →
✓
Add a Get to Green action when anything is Off TrackThe status report won't save without one.Get to Green →
✓
Move the lifecycle stage yourselfIt doesn't update on its own.Lifecycle →
✓
Keep the Benefit Tracker updated tooThe Benefits field and Financial Benefit Savings rating don't replace it.Financials →
✓
Save the Project Brief and PIDEvery project's documents should have both.Folders →

Never

✗

✗

✗

✗
Leave the Original End Date until DeliveryIt locks when you move into Delivery.End date →
✗
Close before the closure reports are approvedProject Closure Report and Executive Summary Closure Report first.Closing →

FinancialsNot recordedOptional Financials tab, reported in the dashboards
SchedulePWA scheduleMicrosoft Planner, with grid, board, timeline, charts, people and goals views

Glossary

Project Hub
ERC's project management reporting tool, replacing PWA.
PWA
Project Web App — the previous tool, retired on 30 September.
Plan
The record for one project in Project Hub, with all its tabs.
Project ID
The reference Project Hub gives a project when it's first saved (e.g. PRJ-1044). Used at the start of every risk and issue name.
Record Owner
Who owns the plan record. You to begin with; your Teams group once it's linked.
Planner
Microsoft Planner, which runs the Tasks tab.
Parent task / subtask
A phase (parent) and the pieces of work inside it (subtasks).
Critical milestone
A zero-duration task marking an important point. Used in the Power BI reports to show progress.
Bucket
A column for grouping tasks in Board view.
RAG
Red / Amber / Green. Risk RAG is worked out from the risk's Likelihood and Impact.
4×4 matrix
The risk assessment grid: Likelihood and Impact, each scored one to four stars.
Flow
An automated action in the command bar — e.g. Escalate Risk to Issue.
Get to Green
The action you must give when any health rating is Off Track — how you'll bring it back.
3-month look-ahead
The three Narrative questions in a status update: expected, achieved, planned. Replaces the Flash Report.
Highlight Report
The one-page report for each project, on the Status Report tab.
Project Lifecycle
The five-stage bar at the top of the plan: Initiation, Planning, Delivery, Monitoring & Controlling, Closure.
Deactivate
The final step of closing a project, which makes the plan read-only.
PMO
Project Management Office.
PID
Project Initiation Document — must be saved in the project's documents.
